# Reach Insight

Instagram PR分析・目的スコア・インフルエンサー推薦の社内ツール開発リポジトリです。**現在はローカルのモックデモです。本番API接続・セキュリティ対応・実サービス側の課金制御は未完了です。**

合意事項と次の実装計画は [プロダクト化の計画](docs/PRODUCT_PLAN.md)、本番利用前の注意は [SECURITY.md](SECURITY.md) を参照してください。

InstagramのPR投稿に反応した人の属性・関心を確認する、日本語の社内管理画面デモ。
**外部APIなしで「登録 → 見積もり → 取得 → 判定 → いいね/コメント/ユニーク集計 → ダッシュボード」が動きます。**

## 起動

必要：Node.js 22以上、npm、Docker Compose。作業ディレクトリは `reach-insight/`。

```bash
cp .env.example .env
npm ci
docker compose up -d db
npm run db:setup
npm run dev
```

http://localhost:3000 を開きます。メール `demo@reach.local`、パスワード `local-demo` でログイン。
「新規分析」→「デモURLを使う」→「見積もりを確認」→「分析を実行」。通常15〜30秒で完了します。
デモ認証は `DEMO_AUTH=true` かつ両Providerがmockの場合だけ利用可能です。
`npm run dev` はNext.jsと独立ワーカーを同時起動します。ブラウザーを閉じても処理は継続します。
本番ビルドのローカル確認は `npm run build` → `npm start`。

管理環境のプレビューはプレビューサービスのURLを使います。`APP_ORIGIN` は実際に使用するオリジンに合わせてください。
停止：Ctrl+C、DB停止：`docker compose stop`。DBデータは名前付きボリュームに保持されます。

## デモ内容

架空ユーザー48人：いいね42人、コメント24人（本人除外後28件）、両方18人、鍵アカ6人、分析済み公開42人。
公開情報が不十分なユーザーは不明。スケボー・ローラー・観戦・366日前の投稿・10代・複数コメントを含みます。
いいねとコメントでそれぞれ1人、全体では重複を除いて1人。インフルエンサー本人は集計から除外します。
取得率はコメント件数と表示コメント件数を比較します。ユニークの表示母数は得られないため取得率は算出しません。
画面のURLや入力したURLから実際のInstagramを取得することはありません。根拠投稿は架空のためリンクを無効にしています。

## 構成

- `src/app/`：認証済みAPI、ログイン
- `src/components/`：ダッシュボード、ジョブ一覧、見積もり、レポート
- `src/domain/`：スケート判定、重複・分母・クロス集計
- `src/providers/`：`DataProvider` / `LLMProvider` とモック・外部アダプター
- `src/worker/`：PostgreSQLキュー、チェックポイント、上限付きリトライ、削除
- `src/fixtures/`：架空プロフィールと投稿
- `src/prompts/`：プロンプト版管理
- `db/schema.sql`：DB定義。判定本体のJSONはスキーマ検証し、ジョブから参照
- `tests/`：F-06-4、F-07、個人情報、DB結合、画面導線

ジョブ取得は `FOR UPDATE SKIP LOCKED` とリースを使い、ワーカーの中断後は期限切れから再開します。
取得ページとカーソルは同一トランザクションで保存。リトライは最大5回、指数バックオフです。
画面の「再開」で保存済みの地点から再実行。設定、モデル、プロンプト版、基準日時をジョブに保存します。
判定キャッシュは30日以内かつ設定・基準日時・モデル・プロンプト版が一致するときのみ再利用します。
本デモではPrismaを介さず、チェックポイントとキューのトランザクションを `pg` で直接実装しています。

## 環境変数

| 変数 | 用途 |
|---|---|
| `DATABASE_URL` | PostgreSQL接続。Composeの既定値はローカル専用 |
| `DATA_PROVIDER`, `LLM_PROVIDER` | 現在のデモは両方 `mock` |
| `DEMO_AUTH`, `DEMO_PASSWORD` | デモ認証の有効化とパスワード |
| `SESSION_SECRET` | 署名用のランダムな32文字以上の秘密値。本格利用前に置換 |
| `APP_ORIGIN` | UIのオリジン。CSRF確認とCookieのSecure設定 |
| `SUPABASE_URL`, `SUPABASE_ANON_KEY` | Supabase Auth設定 |
| `ALLOWED_EMAILS` | 実データ利用を許可する社内メール。カンマ区切り |
| `APIFY_TOKEN` | サーバー専用のApifyトークン |
| `APIFY_*_ACTOR`, `APIFY_ACTOR_BUILD` | 採用Actorとビルド。P0後に確定版を固定 |
| `OPENAI_API_KEY`, `OPENAI_MODEL` | AI Provider用キー・モデル |
| `APIFY_USD_PER_1000_RESULTS`, `LLM_USD_PER_USER` | 実契約の見積単価。未設定は見積不能として扱う予定 |
| `OPENAI_INPUT_USD_PER_MILLION`, `OPENAI_OUTPUT_USD_PER_MILLION` | モデル料金。未設定時は費用未確定 |
| `P0_POST_URL`, `P0_ACTORS`, `P0_MAX_USD`, `P0_INPUT_OVERRIDES` | 明示実行するP0比較用設定 |

秘密情報は `.env` にのみ設定し、`NEXT_PUBLIC_` を付けないでください。実際のキーをソースやログへ出力しません。
デモの `local-demo` とComposeのDBパスワードはローカル専用であり、本格運用の資格情報ではありません。

## Apifyの設定とP0

1. Apifyでトークンを発行し、サーバーの `APIFY_TOKEN` に設定する。
2. [P0調査手順](docs/P0.md)に沿って同じPR投稿で候補を比較する。入力スキーマと課金条件を先に確認する。
3. `P0_MAX_USD` を明示し `npm run p0`。比較スクリプトは結果件数と費用だけ保存し、外部ストレージを削除する。
4. 採用Actor・ビルドを環境変数に固定し、取得上限・全投稿・返信・再開の契約テストを追加する。
5. Supabaseで社内ユーザーを招待、一般登録を無効化し、`ALLOWED_EMAILS` を設定する。
6. 実データ用の見積もり・取得経路と費用計測を検証後に有効化する。

**現時点ではP0実測と実データでのP1完走は未実施です。** Web APIは誤課金を避けるためモック以外の実行を拒否します。
外部Providerアダプターは初期実装で、APIキーだけでは実運用モードへ切り替わりません。残作業はP0文書に記載しています。

## 判定ルールの合意事項

- 除外を優先し、観戦は体験に含めません。AIがnoの場合はスコアのみで可能性ありにしません。
- 性別・年代は本人の明示情報を優先。根拠不足や確信度0.6未満は不明。
- 365日前の同時刻を含み、基準日時より未来の投稿は除外します。画面上の日付は日本時間です。
- 属性分母は分析済み公開アカウント。不明は含み、取得・判定失敗は別表示。
- 設定UI・アカウント入力・比較・ユーザー詳細検索・CSV/PDF出力はP2です。

## 個人情報

- 画像・動画・画像URLはDBにもログにも保存しません。画像確認結果のみ保持。
- 生JSONは画像・認証情報を除去して保存します。ログは一般化したエラーのみ。
- 鍵アカは件数だけ集計し、投稿を取得しません。
- 10代のユーザー名・名前・根拠投稿へのリンクはAPI応答から除きます。
- 個人明細は社内認証が必要。社外向けの出力経路は現在提供しません。P2で追加する出力は集計値に限定します。
- データは初期値90日で削除。ワーカーが起動時と1時間ごとに外部保存先→ジョブ関連行→未参照キャッシュの順で削除します。
- 外部ストレージ削除に失敗した場合はローカル参照を残して再試行します。稼働停止期間中は自動削除できないため、運用では監視が必要です。
- 健康・宗教・政治などの属性は対象外。実運用前にSNSとデータ処理サービスの利用条件を確認します。

## 分析済みユーザー一覧

分析結果の「ユーザー一覧」でタグを比較し、「詳細」から判定条件・根拠・確信度を確認できます。いいね／コメントのタブ連動、検索、タグ・スケート判定の絞り込み、ページ送りに対応。デモでは名前のリンクから架空プロフィールを開き、実データではInstagramプロフィールを開きます。10代はAPI側で名前・リンク・根拠文を伏せます。[更新方法](docs/UPDATE-USER-LIST.md)。既存の分析結果も再分析なしで一覧表示できます。

## 案件の目的スコアと候補推薦（デモ）

左メニュー「候補を探す」で、目的の補足 → 配点確認 → 約100候補のプロフィールと各20投稿を比較 → 最大10人の推薦を試せます。検索の予算上限は3,000円、現在のモック実績は0円です。既存の完了済みPR投稿を選べば、保存済みの反応ユーザーから目的への到達スコアも算出します。

この検索はモック専用で、実Instagram検索やOpenAI接続・サービス側の課金上限制御は未実装です。APIキーを設定するだけでは有料実行に切り替わりません。[算出式・予算管理・残作業・更新方法](docs/CAMPAIGNS.md)を参照してください。

更新時は `npm run db:setup` を再実行し、検索用テーブルを追加してください。既存の分析データは削除されません。
