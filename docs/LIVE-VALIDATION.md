# 実投稿による検証の開始前チェック

投稿URLの指定だけでは外部取得は開始しません。Web経路は引き続きモック限定です。
検証対象と接続情報はローカルで管理し、個別案件との対応や秘密情報を公開GitHubへ保存しません。

1. `.live-test.example.json` を `.live-test.local.json` へコピーし、検証する公開投稿URLを指定します。共有パラメーターは除去します。
2. ローカルの `.env` に `APIFY_TOKEN` と `OPENAI_API_KEY` を設定します。チャット・GitHub・スクリーンショットへキーを貼らないでください。
3. `npm run connections:check` で必須設定の有無と対象URLを確認します。キーの値は出力しません。設定の有無だけを検査し、API呼び出し・有効性確認・料金発生はありません。
4. Apifyの採用候補ごとに、入力・出力・返信・ページング・取得制限・料金・外部保存先の削除権限を確認します。トークンのスコープ不足は必要なAPI操作に対して個別に解決します。
5. 初回は投稿情報1件、限定件数のコメントといいねの取得を段階的に検証する計画を作成します。取得件数上限をActor側で強制できること、起動費用・最低課金・超過停止を確認してから、具体的な費用と取得範囲を提示します。
6. データ取得を確認した後、公開アカウントを少人数で判定します。鍵アカはスキップ、画像は保存せず、外部保存先も確認します。
7. 取得率・欠損・実課金・判定の根拠・保存/削除を確認してから本番Providerを有効化します。

候補推薦1回3,000円の予算を、PR投稿の取得テストの予算として自動流用しません。
Supabaseは社内認証と共有DBで使用します。少量取得の初期検証はローカル環境でも準備できますが、社内公開前には認証・アクセス制御を完成させます。

## 初回の少量テスト案（費用の確認前には実行しない）

- 投稿情報1件とコメント最大20件。返信・いいね一覧・反応ユーザーのプロフィール・画像判定は初回には含めない。
- 先にActorの入力スキーマ・最低課金・料金制限の適用範囲を確認する。公開Storeの入力ページだけでは確認できなかった項目は未確認として扱う。
- PR投稿の初回検証予算は300円でユーザー承認済み。候補推薦の3,000円予算とは別。
- 円換算・税・課金余裕を見てサービス側上限を決め、300円内に収まる制御を確認できるまで有料実行しない。
- OpenAIはApify取得確認後に、個人データを含まない短い入力で疎通を確認する。その後、属性判定の対象人数と費用を別途確認する。
- 実行スクリプトは下記に追加済み。実トークンでの接続と課金上限の実測は未検証。接続情報チェックはAPI通信をしない。

## 少量取得コマンド（予算300円で承認済みの検証）

今回の対象はユーザーが指定した投稿1件です。対象URLはコマンド引数で指定し、リポジトリに固定しません。

```bash
npm run p0:probe -- --url https://www.instagram.com/p/POST_SHORTCODE/
# 上は通信なしの計画表示。確認後に実行する場合だけ --execute を追加
npm run p0:probe -- --url https://www.instagram.com/p/POST_SHORTCODE/ --execute
```

- 投稿情報1件は apify/instagram-scraper のdetails、コメント20件は apify/instagram-comment-scraper。返信は無効。
- 公式APIで両Actorの料金方式と入力スキーマを確認し、取得したビルド番号で実行する。PAY_PER_EVENT以外・追加課金イベント・枠を超える単価なら開始しない。
- API指定上限は投稿0.01米ドル＋コメント0.09米ドル＝合計0.10米ドル。1ドル200円・税/手数料等1.5倍で30円相当の余裕計算。これは為替の実勢値ではなく検証用の換算基準。300円の予算全額を使う設定ではない。
- 無料プランはコメント15件の制限が入力スキーマに記載されている。20件取得を保証しない。
- コメント本文・ユーザー名・画像はローカルへ保存しない。出力は取得件数・表示件数・費用・実行ID・削除状況のみ。
- データセット、Key-value store、キュー、実行記録を削除する。権限不足などで削除・停止を確認できなければ停止し、Consoleでの確認を求める。
- .p0-results/probe-投稿ID.json は排他的に作成する。同一投稿の再実行は自動で行わず、開始通信が不明になった場合もリトライしない。記録を消してむやみに再実行しない。
- OpenAIの通信・属性推定・いいね取得・DB変更はこのコマンドでは行わない。
- 実トークンでのAPI疎通と課金は、Mac上での実行結果を受け取るまで未検証。ローカルの模擬テストを実取得成功として報告しない。

端末の強制終了や通信断があった場合は、自動再実行せず、記録のrunIdとApify ConsoleのRunsから停止状態・利用料・Storageの削除を確認してください。

実装検証：単体・DB結合47件成功、型チェック成功。新規7件は料金方式/スキーマ変更時の停止、取得範囲、データ非保存、開始再試行禁止、削除失敗時の停止を模擬クライアントで検証しています。
