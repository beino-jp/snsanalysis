# 情報不足を改善する検証方針

## 現状の評価

コメント15人を処理したが、性別の根拠があるのは1人、年代は0人。公開情報のある一部の関心は取得できた。
これはAIモデルを変えるだけで解決するとは限らない。非公開、プロフィールの情報量、取得投稿の欠損、入力の切り捨て、自己記述の不足、標本の偏りを分解する必要がある。
次の調査は既存のローカルJSONで実施し、課金を伴う再取得を最初にしない。

## 原因ごとの対策

| 原因 | 最初の確認 | 対策・限界 |
|---|---|---|
| 非公開 | private/isPrivateの判定と件数 | 非公開投稿へ進まない。対象数を増やすか同意された公式集計を使う。非公開ユーザーを情報ゼロ/不関心と混同しない |
| 自己紹介が空・薄い | bio文字数、業務アカウント/個人の区別 | 公開投稿キャプションを追加取得する候補。必要最小限の件数で改善率を測る |
| 投稿が取得できていない | profileInputs.latestPostsの件数/日付保持の不足 | Profile Scraperに含まれる投稿だけでは20件保証にならない。投稿専用Actorで対象者だけ追加取得する契約検証が必要 |
| 1500文字で切捨て | bioが入力を使い切っていないか、実際にAIへ送った投稿数 | bioと投稿に別の枠を割当。重複除去・時系列・根拠を残す要約。費用はトークンで再見積もり |
| 年代・性別の記載なし | 項目別に明示根拠の有無 | 記載がなければ不明は正しい。推測を強めて欠損を隠さない。本人が記載した年齢/生年は基準日時を固定して計算する |
| 少数かつ偏った標本 | コメントの取得順・無料上限・返信/投稿者除外 | 15人では投稿全体を代表しない。取得可能な範囲拡張と標本偏りの表示。いいね人数だけからユーザー一覧取得可能と仮定しない |
| コメントと案件が無関係 | 商品/体験言及・質問・容姿賞賛・絵文字等の分類 | 反応内容と本人の恒常的関心を分離。低情報コメントを案件関心と断定しない |
| 関心ラベルがばらつく | 犬好き/dog lovers等の同義語、引用の対応 | 共通タグへ正規化。案件に必要なカテゴリを先に決め、未該当と不明を区別 |

## 現実的な優先順位

1. **既存データの棚卸し**：情報がない原因を件数で出す。API呼び出しなし。
2. **公開アカウントの投稿補完の小規模比較**：追加取得する前にActorの料金/入力/出力仕様と削除を確認。例えば最大3人、最大10投稿/人等、具体的な追加枠を見積もってから検証する。これは提案であり、まだ有料実行の指示ではない。
3. **改善を測る**：補完前後の属性の明示根拠あり人数、関心タグの根拠あり人数、判定不能の理由、費用/有効判定人数を比較。人数だけ増えて根拠のないラベルが増えたものは改善と扱わない。
4. **より大きな母集団が必要なら**：コメント取得の契約/上限を確認し、全件または定義したサンプルの取得を検討。私的情報へのアクセス、非公開の迂回はしない。
5. **人口属性の本来の情報源**：先方/投稿者にInstagram Insights等の正規に利用できる集計を提供してもらえるなら優先候補。コンテンツ閲覧者、フォロワー、反応者では母集団が違うため、15人の個人推定と混ぜない。任意のアカウントの人口属性が公式APIで取得できるとは案内しない。

## UIで最初に伝えること

- 対象：取得したコメントユーザー。投稿全体/いいね全体の評価ではない。
- 処理完了、公開情報あり、非公開、材料不足を別々に数える。
- 性別・年代それぞれの判定可能率、関心の判定可能率。不明を分母から黙って除外しない。
- 関心タグの人数と根拠のある対象者数、本人の記述とAI解釈を区別。
- モデルの自己申告confidenceは校正済み正答率ではない。百分率の強調をやめ、根拠の有無・直接性・件数・鮮度を表示する案。
- 検証JSON取込は開発者向けの仮導線。最終利用者にはURL→見積もり→取得/分析→結果の一連の画面を提供する。

## スコアと判断

情報充足性と案件適合度を別々に示す。非公開/不足を0点として減点しない。
十分な根拠がある対象の範囲だけで適合を見る場合、その範囲と分母を明示。
閾値や重みは案件目的・ターゲット・サンプル条件から決め、未検証の固定閾値を科学的な基準のように提示しない。

## 再開時の禁止事項

完了済みのprobe/comments/audienceを無条件に再実行しない。
実データJSON、APIキー、個別ユーザーの本文をGitHubやチャットへ出さない。
「不明が多い→見た目や名前で性別/年代を推測」の方向には進めない。
取得済みプロフィールを残せない旧版には戻さない。

## 2026-11-27 実データのオフライン診断結果

ユーザーMacの完了済みaudience JSONを診断し、スクリーンショットで確認。

- 処理15人、公開8人、非公開7人、プロフィール対応なし0人。
- 公開8人のうち自己紹介空4人、投稿本文なし2人、両方なし2人。
- 公開で本文あり6人、投稿本文をAIに使えた対象6人。
- 保存投稿本文56件、1500文字枠で使えた投稿本文56件、同入力枠による切り捨て0人/0文字。
- 根拠ありは性別1/15、年代0/15、関心5/15。AI自己評価100%の項目は9件（精度を示すものではない）。
- 保存前にbio/投稿を切った分量とInstagram上の未取得投稿数は依然不明。

判明した主因は非公開・公開情報不足。今回、1500文字枠による取りこぼしを主因とする仮説は支持されなかった。
投稿本文なしの公開2人は追加確認候補だが、実投稿が存在するかは未確認。投稿ゼロなら取得範囲を増やしても改善しない。
ユーザーは投稿者からInstagram Insightsの提供を受けることは難しいと回答。今後これを前提にした検証・開発計画にしない。
他人の年代・性別の記載不足をAIの推測で埋める方針にはしない。性別・年代を高い網羅率で得る要件と公開データだけの制約が両立しない可能性を説明する。
