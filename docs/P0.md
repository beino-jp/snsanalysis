## 比較手順

1. 同一の公開PR投稿を選び、観測時の表示いいね数とコメント数を記録する。
2. ActorのInput/Outputスキーマを確認。ログイン・cookie要否、暗黙上限、日付フィルタ、返信、画像保存とログの保持を確認する。
3. `.env` に `P0_POST_URL`, `APIFY_TOKEN`, `P0_MAX_USD`（候補全体の上限）を設定する。値はコミットしない。
4. 入力が異なるActorには `P0_INPUT_OVERRIDES` をJSONで指定する（キー＝actor ID、値＝入力オブジェクト）。デフォルトのpostUrlsを無条件で全Actorに流用しない。
5. `npm run p0`。候補ごとに予算を等分し `maxTotalChargeUsd` を渡す。Actorが上限に対応することを事前確認する。
6. `.p0-results` に個人情報を含まない件数・所要秒数・実課金・1,000ユニークユーザー単価を出力する。表示数を使って取得率を計算し比較表へ追記する。
7. 同条件で再実行し、増分・重複課金・再開可能性を確認。異なる規模の投稿でも欠損やサンプリング偏りを確認する。
8. プロフィール・365日投稿・返信については別入力で契約テストを行う。認証情報は専用運用アカウントで管理する。
9. 外部ストレージの削除をConsoleで確認。削除失敗時はその完了まで運用を始めない。

## 採用条件

取得率、安定性、速度、総費用、再開性、レート制限、ユーザーIDの一致、鍵アカの識別、画像を残さない運用を合わせて評価する。
「全件取得」の宣伝文だけで採用しない。上限・取得不能はUIの事前見積もりに明示する。
