# 実投稿による検証の開始前チェック

投稿URLの指定だけでは外部取得は開始しません。Web経路は引き続きモック限定です。
検証対象と接続情報はローカルで管理し、個別案件との対応や秘密情報を公開GitHubへ保存しません。

1. `.live-test.example.json` を `.live-test.local.json` へコピーし、検証する公開投稿URLを指定します。共有パラメーターは除去します。
2. ローカルの `.env` に `APIFY_TOKEN` と `OPENAI_API_KEY` を設定します。チャット・GitHub・スクリーンショットへキーを貼らないでください。
3. `npm run connections:check` で必須設定の有無と対象URLを確認します。キーの値は出力しません。設定の有無だけを検査し、API呼び出し・有効性確認・料金発生はありません。
4. Apifyの採用候補ごとに、入力・出力・返信・ページング・取得制限・料金・外部保存先の削除権限を確認します。トークンのスコープ不足は必要なAPI操作に対して個別に解決します。
5. 初回は投稿情報1件、限定件数のコメントといいねの取得を段階的に検証する計画を作成します。取得件数上限をActor側で強制できること、起動費用・最低課金・超過停止を確認してから、具体的な費用と取得範囲を提示します。
6. データ取得を確認した後、公開アカウントを少人数で判定します。鍵アカはスキップ、画像は保存せず、外部保存先も確認します。
7. 取得率・欠損・実課金・判定の根拠・保存/削除を確認してから本番Providerを有効化します。

候補推薦1回3,000円の予算を、PR投稿の取得テストの予算として自動流用しません。
Supabaseは社内認証と共有DBで使用します。少量取得の初期検証はローカル環境でも準備できますが、社内公開前には認証・アクセス制御を完成させます。

## 初回の少量テスト案（費用の確認前には実行しない）

- 投稿情報1件とコメント最大20件。返信・いいね一覧・反応ユーザーのプロフィール・画像判定は初回には含めない。
- 先にActorの入力スキーマ・最低課金・料金制限の適用範囲を確認する。公開Storeの入力ページだけでは確認できなかった項目は未確認として扱う。
- PR投稿の初回検証予算として300円を提案。候補推薦の3,000円予算とは別であり、承認済みではない。
- 円換算・税・課金余裕を見てサービス側上限を決め、300円内に収まる制御を確認できるまで有料実行しない。
- OpenAIはApify取得確認後に、個人データを含まない短い入力で疎通を確認する。その後、属性判定の対象人数と費用を別途確認する。
- まだ実行スクリプト・実接続・料金上限のサービス側検証は未完了。接続情報チェックはAPI通信をしない。
