# 先方がURLだけで試せる環境の受け入れ条件

> 2026-11-27更新：配備方針はCloudflare主体へ訂正。VPS契約は不要。最新の実装順は [CLOUDFLARE-ARCHITECTURE.md](CLOUDFLARE-ARCHITECTURE.md) を参照。以下のVPS/Docker手順は任意の代替案であり、ユーザーへ契約を要求しない。

## ゴール（2026-11-27合意）

先方は招待メールからログインし、Instagram投稿URLを貼り付ける。
費用と対象範囲を確認して開始し、進捗と結果をブラウザで確認できる。
ZIP、ターミナル、APIキー、JSONファイルの操作を先方に要求しない。
「クライアント側」は先方がブラウザから使うという意味。ブラウザから直接Apify/OpenAIへ通信しない。秘密はサーバー側に置く。
非公開・投稿なし・根拠不足は不明でよい。画像だけで人口属性を断定しない。

## 実装順

1. **URLから実データ分析を開始するWeb接続（次の主要作業）**
   - 少量検証で成功した取得・プロフィール・AI分析をサーバーのジョブへ移す。
   - まずコメント最大20件/公開プロフィール最大20人の限定版として範囲を明示する。候補探索の100人×20投稿と混ぜない。
   - POSTの重複対策、DBの排他、実行予約と月間上限、課金不明時の停止、途中保存・再開・外部削除を実装する。
   - 初回から大規模実行を許可せず、外部料金・取得条件を事前確認し、画面の確認後に有料処理を始める。
2. **先方向けの導線**
   - 必須は投稿URLのみ。案件名は任意、詳細設定は折りたたむ。
   - 状態を「準備中→取得中→分析中→結果」で表示。タブを閉じてもサーバーの処理は続き、履歴から戻れる。
   - 非公開・情報不足を処理失敗として扱わず、判定できた人数と分母を表示する。
   - エラーは、起きたことと次に押すボタンを示す。APIの専門語や秘密を出さない。
   - 取得JSONのアップロードは管理・検証用に分離し、通常利用の入口にはしない。
3. **共有環境の設定と公開**
   - 専用の開発サーバー、Supabase開発用DB/認証、専用APIキー、許可メールを設定する。
   - 招待以外の登録を無効にし、先方と社内の表示範囲を整理する。既存の社外向けは集計のみという要件との整合を確認する。
   - Cloudflare DNS→サーバーのHTTPS入口→Web/API→DBキュー/ワーカー。固定費とAPI費を合算し月額1万円の計画を確認する。
   - PCとスマホで実データ1本を完走、重複実行・途中失敗・権限外アクセスを検証してから案内する。

## 今回整えた土台

- 投稿URLを先に入力し、案件名・基準日の詳細は任意設定へ移した（現在の実行経路は依然モック）。
- 招待ログインではデモのパスワード説明やデモメールを表示しない。
- productionではDEMO_AUTH=false、HTTPS、DB、Supabase、許可メール、専用セッション鍵を要求する。
- セッションの許可メールを各リクエストで確認し、許可リスト変更をプロセスへ反映すると既存セッションも拒否する。
- 更新系リクエストは設定したAPP_ORIGINと一致することを要求する。
- Dockerfileとdeploy/compose.yamlを追加。Webと常駐ワーカーを分離、マイグレーション後に起動、外部公開ポートはHTTPS入口のみ。
- /api/healthは設定とDB到達性だけを確認し、秘密やDBエラー本文を返さない。

## サーバー管理者向けの準備手順（まだ公開しない）

deploy/test.env.exampleをdeploy/test.envへコピーし、専用の設定を入力する。
SESSION_SECRETはランダムな32文字以上を生成し、既存サンプルを使わない。
Supabaseでは招待したテスターと許可メールだけを使い、公開サインアップを無効にする。
DBはサーバー側からだけアクセスし、接続先のTLS・ポリシー・バックアップを確認する。
環境ファイルはGit/Docker build contextから除外済み。パスワードやキーをチャットに貼らない。

```sh
docker compose -f deploy/compose.yaml build
docker compose -f deploy/compose.yaml up -d
```

このコマンドは、ドメイン・DNS・ファイアウォール・Supabaseを設定したサーバーで管理者が使うもの。ユーザーMacや先方に実行させない。
初期のDATA_PROVIDER=mock/LLM_PROVIDER=mockは招待ログイン・操作確認用。実データWeb実行が完了したことを意味しない。
本番サーバー契約・公開URL・招待・実APIの自動完走はまだ未完了。
Caddyの証明書発行にはDNSが正しいことと80/443到達性が必要。Cloudflare SSL/TLSはサーバー側証明書を検証する設定にし、Flexibleを使用しない。
バックアップ、復旧、ログイン/ジョブ作成のレート制限、費用の月間停止、外部保存先削除失敗の運用は別途完了が必要。

## 2026-11-27の検証状況

- 型チェック・本番ビルド成功。単体/HTML/認証テスト66成功、DB5件は今回スキップ。
- Composeはexample環境ファイルに差し替えた構成検証に成功。
- 作業環境のHTTPS検査用CAが必要だったため、Docker buildでは任意のBuildKit secret `build_ca` でCAを一時提供する方式を追加。TLS検証は無効にしない。CAをランタイムへコピーしない。
- E2EにURLだけの登録ケースと任意設定を開く操作を追加。今回ブラウザーでの実行は未完了。
- npm auditは12件（moderate2/high8/critical2）を報告。現lockfileでは自動修正候補なし。criticalはvitest/tinypoolの開発ツールを含む。現Dockerはワーカーのtsxも含め開発依存を持つため、外部公開前に依存更新・ランタイム依存の分離・回帰確認が必要。監査結果を無視して先方に公開しない。
