# プロダクト化の決定事項と作業計画

この文書は開発中に合意した方針を保存したものです。認証情報・個別案件の内部事情・会話原文は含めません。

## 合意済み

- 社内利用。利用者は5人未満。
- 月額運用予算は10,000円以内を目指す。固定費・API利用料・税・為替余裕を含めて管理する。
- ドメインは未取得。取得後はCloudflareでDNSを管理する。
- コード管理先は `beino-jp/snsanalysis`。
- Instagramを優先。X対応は後続。
- PR投稿に反応したユーザーの公開情報から属性・関心を集計する。
- 目的を入力し、不足条件を確認したうえで評価基準を決める。配点と根拠を表示し、良し悪しの理由を説明する。
- 新規候補は公開検索から発見し、約100アカウントのプロフィールと直近20投稿までを比較して最大10人推薦する方式。
- 推薦検索1回の外部API予算上限は3,000円。条件に合わなければ10人未満でも返す。
- この候補検索では反応ユーザーの深掘り取得は行わない。発信内容の適合度と実際に届く層の評価を区別する。
- データ取得とAI判定はProviderインターフェースで分離する。
- 外部APIを使わず、モックだけでも導線を確認できるようにする。
- 画像は保存しない。個人明細・生データは原則90日で削除。社外向けは集計値のみ。
- 10代と推定した人の識別情報は伏せる。健康・宗教・政治などの敏感な属性は推定しない。
- OpenAIは既存アカウント内に、このツール専用ProjectとAPIキーを分ける。別プロダクトのキーは共有しない。

## 構成案（サービス選定・契約は未確定）

固定費を抑える案：Cloudflare DNS + 小型VPS（Next.js・API・ワーカー）+ Supabase（PostgreSQL・招待制認証）+ Apify + OpenAI。
Vercelを使う案も検討したが、ワーカー用サーバーとの費用をまとめるため、初期はVPSに寄せる案を提示。
Supabase無料枠は検証候補。本番のバックアップ・休止条件・保持期間・復旧要件を確認してから決める。
VPSのOS更新、TLS、ファイアウォール、監視、バックアップを含む運用が必要。

## 月額予算の仮配分

| 枠 | 月額予算 |
|---|---:|
| サーバー・バックアップ・ドメイン相当 | 2,000円 |
| Apify・OpenAI利用料 | 6,000円 |
| 税・為替・追加費用の余裕 | 2,000円 |
| 合計 | 10,000円 |

料金の確約・契約見積もりではない。3,000円を使い切る検索はAPI枠6,000円なら月2回程度。
既存PR投稿の詳細分析もAPI枠を使う。Apify月額の含有クレジットと従量費を二重に加算しない。
月額上限はまだ実装していない。OpenAIの予算通知だけでは実行停止にならないため、アプリでも月間の実績・予約・追加実行を制御する。

## 本番公開前に実施すること

1. **依存関係とセキュリティの確認**
   - ユーザー環境のnpmインストールで脆弱性の報告があった。監査・更新・回帰確認を行う。
   - 本番のDEMO_AUTHを無効にし、署名鍵・DB資格情報を発行する。
2. **社内認証・DBアクセス制御**
   - Supabaseで招待制、一般登録無効、社内メールの許可リスト。
   - 管理者MFA、サーバー専用接続、最小権限。RLSを使うテーブルはポリシーを実装・検証。
   - ログイン・ジョブ作成のレート制限、操作監査、セッション失効・退職者アクセスの運用。
3. **ApifyのP0実測**
   - 対象PR投稿・調査予算・候補Actorを決め、取得率・費用・欠損・再開性を比較。
   - データの保存・画像非保存・削除を外部サービス側でも確認。
4. **実データProviderとAI接続**
   - PR取得アダプターの契約テスト、候補探索用の実DataProviderを実装。
   - 目的整理用OpenAI Providerを実装。現在の聞き返しはルールベース。
   - 現在Web経路はモック限定。APIキーだけで有料処理が始まる状態にはしない。
5. **課金制御**
   - 実サービス側の課金上限、トークン上限、費用照合、未知請求時の停止。
   - 検索1回3,000円と月額全体10,000円の両方を管理。
6. **データ保護と運用**
   - 保存期限・削除失敗を監視。外部ストレージも削除。
   - バックアップの暗号化・復旧テスト・個人データの残存期間を決める。
   - 開発と本番のDB・キーを分離。ログの個人情報と秘密情報を除去。
7. **社内の検証環境**
   - ブラウザーE2E、実投稿1本での完走、人数・費用・精度を確認。
   - SNS・外部データ取得サービスの利用条件を確認してから本格運用。
